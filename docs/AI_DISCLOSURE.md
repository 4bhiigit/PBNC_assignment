# AI Disclosure & System Transparency

This document provides full transparency regarding the use of Artificial Intelligence in the **Document Intelligence & Question Extraction Service**, covering both the development process and the runtime system architecture.

---

## 1. Development-Time AI Disclosure

### 1.1 Assistant Usage
- **AI Tool Used**: Antigravity / Gemini code assistant.
- **Scope of Assistance**:
  - Drafting initial boilerplate for SQLAlchemy async models and Alembic migrations.
  - Designing regex edge-case patterns for roman, devanagari, and stacked option permutations.
  - Generating sample test document schemas and synthetic evaluation test cases.
  - Drafting OpenAPI and Postman collection definitions.

### 1.2 Human Supervision & Verification
- All architectural decisions (ADR-001 through ADR-007), tenant security models, database schemas, and pipeline staging were designed and reviewed by the lead engineer.
- Every API endpoint and background worker task was verified with executable automated tests (171 unit and integration tests passing).
- Code quality, type annotations, and linting were validated with `mypy` (strict mode) and `ruff`.
- All benchmark metrics in `docs/demo_evidence/` were generated by running the actual test execution engine, not synthesized.

## 2. Runtime System AI Disclosure

### 2.1 Runtime LLM Integration
- **Model**: `gemini-3.6-flash` (via the `google-genai` Python SDK).
- **Role in Service**: Optional structured extraction engine (`EXTRACTOR=hybrid` or `EXTRACTOR=llm`).
- **Input Context**: Page image bytes and/or extracted raw text layer tokens.
- **Output Schema**: Strict Pydantic model (`PageExtractionModel`) with constrained JSON schema enforcement.

### 2.2 Safety, Grounding & Integrity Safeguards
1. **Prompt Injection Defense**: Document text is treated as untrusted data. The LLM is invoked only with extraction instructions that forbid executing document instructions or solving questions.
2. **Grounding Verification**: Extracted text is checked against raw page tokens using `rapidfuzz` Levenshtein token similarity. Questions falling below 0.60 grounding are flagged as `LOW_GROUNDING`.
3. **Deterministic Fallback**: If LLM API quotas are exhausted (HTTP 429) or network timeouts occur, the pipeline falls back immediately to `RulesExtractor` and attaches the `LLM_FALLBACK_USED` audit flag.
4. **No Generative Answering**: The model is forbidden from solving questions. Answers are extracted solely from explicit document keys or marked `not_found`.
